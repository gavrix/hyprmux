What goes in a tile

More than terminals.

A tile holds a terminal, a web page, a document, or a device. Put them side by side on one workspace, and move between them with the same keys.

Simulators in a tile.

Live iOS Simulator and Android Emulator screens. Click and drag to touch, type to use the keyboard, and use the buttons for Home, Lock, Back, and Recents. Simulator.app isn't needed.

Editors too. Experimental

VS Code, Cursor, and other Electron apps open in tiles through an adapter. Zed comes from a fork that draws straight into tiles. Build your own with the client protocol, in Swift or Rust.

  • Activity on every tile

    Orange for working, red for needs you, green for done. Workspace pills count them, and a notice tells you when an agent waits for an answer.

  • hyprmuxctl

    A hyprctl-like CLI. Read screens, send text and keys, open tiles in the background, and stream events. Hooks run commands when events happen.

  • Web tiles over CDP

    agent-browser, Playwright, and Puppeteer drive Chromium tiles. A banner and a cursor show what the agent does, and Stop takes control back.

  • Sessions that come back

    Relaunch and get back your workspaces, layouts, directories, programs like nvim, and agent sessions for pi and Codex.

  • Any terminal agent

    Claude Code, Codex, pi, opencode, and the rest run as they are. A one-line hook reports their state, and pi ships with an extension.

  • A bundled skill

    hyprmuxctl skill install gives your agent a skill that teaches it to find, read, and drive other tiles.

The rest of Hyprland

Workspaces, groups, scratchpad.

The parts of Hyprland you miss on a Mac, plus a few it never had.

  • Workspaces ⌘1…9

    Numbered workspaces that slide like Hyprland's, with optional names.

  • Groups ⌘G

    Several windows as tabs in one tile. ⌃Tab switches them.

  • Scratchpad ⌘S

    A hidden workspace that slides in over the current one, and away again.

  • Layouts ⌘U

    Save a workspace as a template, then summon it again with its programs and agents.

  • Pickers ⌘/

    fzf-style lists for workspaces, apps, and an app's windows, plus a menu of all of them.

  • Floating and fullscreen ⌘F

    Float any tile, maximize it, or make it fill the screen. Then tile it again.

  • Passwords

    Fill web fields and terminal password prompts from 1Password, after Hyprmux checks the origin.

  • Notifications

    Config errors and terminal notifications, styled like your terminal.

  • Keycast

    Shows each shortcut as you press it, for recordings and screen sharing.

FAQ

Questions.

How is it different from cmux?

Both are native macOS apps built on libghostty, with a scriptable browser and a CLI. cmux is a terminal first: vertical tabs with git branches and ports, split panes, notification rings, remote SSH workspaces, and an iOS companion app. Hyprmux is a tiling environment: Hyprland's dwindle layout, workspaces, groups, and animations, a hyprland.conf-style config, and tiles that hold simulators and editors as well as terminals and web pages. Pick cmux for a polished terminal with tabs. Pick Hyprmux if you want Hyprland's way of working.

How does it compare to herdr?

herdr runs inside your terminal, like tmux. It keeps agents running in a background server, lets you detach and reattach, works over SSH, and runs on macOS, Linux, and Windows. Hyprmux is a native Mac app with a graphical compositor. It tiles more than terminals, and it shows agent state on tiles and workspaces. It doesn't run headless, and when Hyprmux quits its programs stop. On relaunch it brings back the layout and resumes agent sessions.

Why not tmux or Zellij?

They run in any terminal, on any machine, over SSH, and sessions survive when you disconnect. Hyprmux can't do that. In exchange, it draws real tiles: smooth animation, gradient borders, blur, mouse resizing, and tiles that aren't terminals at all. You can still run tmux inside a Hyprmux terminal.

Why not AeroSpace, yabai, or Amethyst?

Those tile the real windows of every app on your Mac. That's their strength, and they work around macOS limits to do it. Hyprmux tiles only inside its own window, so it controls every pixel: animations, borders, blur, and the same keys everywhere. It holds terminals, web pages, simulators, and supported apps, not arbitrary Mac windows. They work fine together, because to a tiling window manager Hyprmux is one window.

Is it Hyprland for macOS? Can I use my hyprland.conf?

It borrows Hyprland's ideas, not its code. The config syntax is hyprlang, with the same sections, bind lines, dispatchers, gradients, and bezier animations, so much of a general, decoration, animations, and bind setup carries over. Parts that only make sense on Linux, like monitors and Wayland window rules, don't apply. Hyprmux isn't affiliated with Hyprland.

How does it relate to Ghostty?

Hyprmux uses libghostty to draw terminals, the way apps use WebKit to draw web pages. It isn't a fork of Ghostty. Your Ghostty config, themes, and fonts apply to Hyprmux terminals. Ghostty has its own splits and tabs. Hyprmux adds a tiling layout, workspaces, tiles that aren't terminals, and scripting.

Which coding agents work with it?

Every agent that runs in a terminal: Claude Code, Codex, pi, opencode, Gemini CLI, Aider, and the rest. To show an agent's state on its tile, a hook calls hyprmuxctl agent-state. pi has a bundled extension that does it. Session restore resumes pi and Codex sessions.

Why one window?

macOS gives apps no way to move other apps' windows between Spaces, and little control over how those windows animate. Inside its own window, Hyprmux owns the whole layout, so tiling, workspaces, and animation behave the same every time. Press ⌃⌘F to make that window your whole screen.

What's experimental?

Apps in tiles (VS Code, Cursor, other Electron apps, and Zed), and the client protocol for building your own. Electron apps work through an adapter. Drag and drop doesn't work in them, and their menu bar isn't reachable, so use the command palette instead.

What are the limitations?

One monitor: there's no multi-display support yet. Only terminal tiles support reads and input from hyprmuxctl. The WebKit engine has no passkeys, and Chromium supports phone and security-key passkeys, not Touch ID. Simulator tiles and the libghostty build depend on private or fast-moving APIs, so an Xcode or libghostty update can break them.

Is it free? What do I need?

Yes. Hyprmux is free and open source under the MIT license. It needs macOS 14 or later on Apple silicon. iOS Simulator tiles need Xcode, and Android Emulator tiles need the Android SDK emulator.
